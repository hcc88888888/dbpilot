# DBPilot 监控与告警管理控制面设计

## 目标与范围

建立 DBPilot 的监控与告警管理闭环：接收 Agent 指标，评估告警规则，维护告警事件状态，按通知策略发送应用内、邮件和 Webhook 通知，并提供实时概览、规则、通知策略、静默和告警详情的自研前端接口。

控制面是告警事实来源。Prometheus 与 Alertmanager 仅通过兼容适配边界接入或导出，不能绕过 DBPilot 的租户、项目、权限、审计与事件状态模型。

一期包含静态阈值、持续时长、缺失数据、变化率及 `avg`、`max`、`min`、`sum`、`count` 聚合。PromQL 子集、跨指标表达式、动态基线和 AI 归因不在一期实现。

## 架构

```text
Agent -> Server Ingest -> 指标时序存储
                          |- 内置规则评估器 -> 告警事件 -> 通知分发
                          |- Dashboard / 告警中心 API
                          |- Prometheus 兼容导出
外部 Prometheus / Alertmanager -- 兼容适配边界 --|
```

服务端按以下模块划分：

- 指标接入：验证 Agent、Remote Write 或兼容 Webhook 数据，规范化租户、项目、资源和指标标签，并写入时序存储。
- 规则评估：按租户、项目和资源范围运行已启用规则，输出 pending、firing 或 resolved 判定。
- 告警事件：基于稳定指纹去重，维护事件状态、证据、关联资源、根因线索和处置记录。
- 通知分发：基于策略、模板、静默窗口和限流投递应用内、邮件或 Webhook 通知；失败会记录并按指数退避重试。
- 兼容适配：Prometheus 查询/导出及 Alertmanager 入站 Webhook 只做协议转换；授权和事件状态必须仍由 DBPilot 控制面执行。

一期使用 PostgreSQL 保存配置、事件、审计、投递记录和按时间分区的短期指标样本。持久化接口不得依赖 PostgreSQL 特有调用，以便后续将指标样本迁移到 TimescaleDB 或 ClickHouse，而不改变规则、事件与 API 模型。

## 领域模型

### AlertRule

规则包含：ID、租户、项目、名称、启用状态、指标选择器、资源标签过滤、聚合、比较运算、阈值、持续时长、评估周期、缺失数据策略、严重级别和通知策略引用。

规则创建和启用时必须校验表达式、标签、资源范围、通知策略引用及评估周期。无效规则不允许启用。

### AlertEvent

事件状态为 `pending -> firing -> acknowledged -> resolved`。稳定指纹由租户、项目、规则和规范化资源标签构成。相同指纹的重复评估只能刷新同一事件；恢复必须写为原事件的状态变更，不能创建无关事件。

事件保存首次触发、最近触发、确认、恢复时间，关联资源、证据样本、根因线索、确认/关闭处置记录及通知投递结果。

### NotificationPolicy、Template 与 Silence

通知策略按严重级别、标签、项目与时间窗口路由至应用内、邮件或 Webhook。模板分别定义标题、摘要、资源、趋势链接和恢复文案。通知投递以事件/状态转换/渠道为幂等键，并采用有限指数退避。

静默支持按事件指纹、资源、标签或时间范围匹配，要求记录创建人、原因、有效期和审计信息。静默阻止通知，但不停止规则评估和事件审计。

### AlertAuditLog

规则、策略、模板、静默的创建/更新/删除，告警的确认/恢复，以及通知投递/失败/重试均写入不可变审计记录。

## 规则与评估

一期规则引擎支持：

- 静态阈值：按比较运算符判断聚合结果。
- 持续时长：连续满足条件后由 pending 进入 firing。
- 缺失数据：每条规则明确选择 `ignore`、`alert` 或 `resolve`。
- 变化率：以固定采样窗口计算单指标变化率。
- 聚合：`avg`、`max`、`min`、`sum`、`count`。

评估结果和输入样本必须包含租户、项目、实例、组件、角色、主机、采样时间及资源标签。资源维度缺失或不完整时不得伪造 healthy 状态；按规则的缺失数据策略处理并留下评估证据。

评估器自身的延迟、失败、无数据和队列积压产生系统级健康告警，防止告警系统失明。

## 权限与安全

- 所有配置、事件、静默与通知策略绑定租户和项目。
- 平台管理员拥有跨项目只读/管理能力；项目成员仅操作获授权项目。
- SMTP 密码、Webhook Token、外部系统凭据只保存 Secret 引用，永不出现在 API 响应、日志或审计正文。
- Webhook 仅允许 HTTPS、允许域名列表和请求签名；重定向、私有网络目标和未允许域名默认拒绝。
- 通知失败不会中断评估；失败、重试和最终放弃均有可查询状态和审计记录。

## API 与前端边界

后端提供租户/项目作用域的 API：监控概览、告警列表和详情、规则 CRUD/启用、通知策略 CRUD、模板 CRUD、静默 CRUD、事件确认/恢复及通知投递历史。

前端全部自研并复用 DBPilot 企业后台视觉与权限模型。新增页面为：监控概览、告警列表、告警详情、规则管理、通知策略、模板管理和静默管理。页面通过统一 API 获取数据，不直接调用 Agent、PostgreSQL、Prometheus 或 Alertmanager。

## 测试与验收

1. 单元测试覆盖规则校验、聚合、持续时长、缺失数据、指纹去重、恢复、静默、路由、模板渲染、投递重试和 Secret 脱敏。
2. 集成测试使用真实 Agent 接入路径，验证指标到事件、通知和审计记录的完整链路。
3. Docker 测试环境使用隔离网络、无主机端口、健康检查和测试 SMTP/Webhook 服务；必须验证成功、失败、重试和静默路径。
4. Kylin V10 容器中运行真实 Agent，验证 Agent -> Server -> 规则评估 -> 告警事件闭环；通知渠道可由容器内测试端点替代。
5. 验收通过标准：可创建规则；由 Agent 指标触发/恢复/确认事件；监控概览正确显示；应用内、邮件和 Webhook 均可投递；静默阻止通知但保留审计；所有动作遵守租户、项目和权限边界。

## 分阶段交付

1. 控制面领域模型、PostgreSQL 持久化、租户项目授权和 API 基础。
2. 指标时序存储与规则评估器，完成事件状态机、指纹与审计。
3. 通知策略、模板、应用内/邮件/Webhook 分发及静默。
4. Dashboard/告警中心 API 与自研前端页面。
5. Prometheus/Alertmanager 兼容适配。
6. Docker/Kylin 端到端验证和运维文档。
